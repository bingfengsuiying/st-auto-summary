# 剧情自动总结 · Auto Summary

一个 SillyTavern 扩展：自动或手动把聊天压缩成剧情总结，写进世界书作为常驻设定，辅助后续生成。

- **大总结**：每 M 层吞并上一份大总结，始终覆盖第 1 层到当前；字数上限随覆盖楼层增长（500 字起，每 100 层 +300），重要剧情写清楚、次要内容可压缩；
- **小总结**：按你设定的楼层范围生成，保留细节；
- 自动大 / 自动小可以**分开开关**，也可以一键全开 / 全关；
- **手动生成的总结永远不会被自动清理**。

兼容 **SillyTavern 1.13.x ~ 1.18.x**，桌面与手机浏览器都能用。

> A SillyTavern extension that summarizes the chat into world info entries. Big summaries roll up and absorb previous ones; small summaries use player-defined ranges. Auto big/small toggles are independent.

---

## 它怎么工作

### 自动总结

- **自动小总结**：每 N 层（默认 50）触发一次，总结“上次覆盖的位置 → 当前里程碑”这一段；
- **自动大总结**：每 M 层（默认 100）触发一次，把**上一份大总结**和新增楼层一起喂给模型，产出一份新的概览，始终只有一条、覆盖第 1 层到当前；
- 自动大 / 自动小是**两个独立开关**，可以只开小、只开大、都开或都关；
- 「全部开启 / 全部关闭」一键切换两者（总开关关闭时两个都不会跑）。

### 手动总结

- **立即小总结**：自己填起始楼层、结束楼层，总结这一段；
- **立即大总结**：只需要填结束楼层，插件会从上次大总结的进度继续补到这一层，保证覆盖全部剧情（不会出现只总结后半段却标成“第 1-N 条”的情况）；
- 生成后弹窗预览正文，可编辑，再选择：
  - **替换总结**：覆盖同类型最新的一条；
  - **融合总结**：旧正文 + 新正文合并成一条，范围取并集；
  - **取消总结**：不写入，也不推进进度。

### 写入世界书

- 优先写进当前聊天绑定的世界书（Chat Lore）；
- 没有绑定就自动创建 `自动总结 - 角色名 - xxxx` 并绑定到当前聊天；
- 也可以在设置里指定一本世界书（需要你自己在酒馆里激活）；
- 条目以“常驻（constant）”注入提示词，默认插在聊天记录末尾（小 depth 4 / 大 depth 8），不会修改任何聊天记录。

## 保留与清理规则

| 类型 | 规则 |
| --- | --- |
| 自动小总结 | 最多保留最近 N 条（默认 3），更旧的自动删除 |
| 手动小总结 | **永不自动删除**，想删只能点「清理总结条目」 |
| 大总结（自动或手动） | 始终只有一条，新的会吞并旧的内容，范围更新为第 1 层到结束楼层 |
| 旧版本条目（没有来源标记） | 按“手动”处理，不会被自动清理 |

## 安装

### 酒馆内安装（推荐）

扩展 → **Install extension** → 填仓库地址：

```
https://github.com/bingfengsuiying/st-auto-summary
```

刷新页面即可。

### 手动安装

把整个 `st-auto-summary` 文件夹放到：

```
SillyTavern/public/scripts/extensions/third-party/st-auto-summary/
```

确认结构是 `third-party/st-auto-summary/manifest.json`，不要多套一层同名文件夹。
手机用文件管理器 / ZArchiver 复制，Termux 装的一般在 `~/SillyTavern/...`，然后刷新页面。

## 使用

打开「扩展」面板里的「剧情自动总结」：

1. **自动总结（总开关）**：不打开时自动流程完全不动；
2. **自动小总结** / **自动大总结**：分别控制两种自动总结；
3. **全部开启 / 全部关闭**：一键切换两者；
4. 小总结间隔、大总结间隔：按你的习惯设置（默认 50 / 100）；
5. 「自动小总结保留」：只约束自动生成的小总结；
6. 注入位置默认「聊天记录末尾」，也可以选「角色定义前」。

手机端面板会自动排在扩展设置区最前面；点输入框旁的**魔杖菜单**有快捷开关和「立即小总结」。

状态行会显示，例如：

```
共 137 条 · 下次小总结在 150 条（还差 13） · 下次大总结在 200 条（还差 63）
自动：小总结开 / 大总结开（总开关已开）
世界书：《自动总结 - 小蝶 - a1b2》（小 自动 2 / 手动 1 · 大 1）
上次：小总结 · 20:15
```

## 生成与成本

- 使用当前接口的 `generateRaw` 静默生成，不会在聊天里留下消息；
- 每次最多把 `maxInputChars`（默认 8000 字符）的聊天内容喂给模型，超长消息会逐条截断，优先保留较新的内容；
- 提示词要求：小总结 250 字以内；大总结按覆盖楼层给上限（见下表），并按剧情重要度在上限内伸缩；
- 首次开启大总结且历史很长时，受输入上限影响只能保留最近部分；可以调高 `maxInputChars`，或先用小总结/手动大总结分段补齐；
- 失败会提示原因，并进入 60 秒冷却。

## 大总结字数上限

覆盖楼层越多，允许的篇幅越大；模型会按重要度分配，重要剧情多写、次要日常压缩，不强制写满。

| 覆盖楼层 | 字数上限 |
| --- | --- |
| 1-100 | 500 |
| 101-200 | 800 |
| 201-300 | 1100 |
| 301-400 | 1400 |
| 每 +100 层 | +300（最多 4000） |

## 世界书条目长什么样

- 注释：`[自动总结][自动小] 第 51-100 条`、`[自动总结][自动大] 第 1-200 条`、`[自动总结][手动小] 第 10-20 条`
- 常驻、关键词为空，所以一定会参与提示词；
- 关闭递归（excludeRecursion / preventRecursion），避免总结里的名字触发别的条目；
- `automationId` 为 `st-auto-summary`；
- 同一范围重复总结会更新原条目，不会堆重复。

## 排障

**提示 Authorization Required / API returned an error**
接口密钥或模型配置有问题，先在酒馆里正常发一条消息确认能生成。

**点了没反应 / 提示“当前聊天还没有保存”**
新聊天需要先有一条消息并落盘；或者先在设置里指定一本世界书。

**大总结的结束楼层改不小**
大总结不能早于上次大总结的进度，否则会丢剧情；想从头重来先点「清理总结条目」。

**世界书里没有总结**
打开世界书面板确认书是否存在、条目是否被禁用；指定世界书模式下要确认这本书已经激活。

**手机上没有面板**
检查路径层级，强制刷新页面；确认「管理扩展」里扩展是启用状态。
